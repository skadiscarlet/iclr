## 4. B02 — 修复实验公平性与输入契约

### 4.1 代码范围

从现有 `src/sbs/views.py`、`schema.py`、`replay.py`、`isolation.py`、`static_check.py`、`registry.py`、`reports.py` 最小修改。现有 R01 `RunManifest` 写死零调用，**保留 fixture 模式**，新建或扩展区分的 frozen-pilot manifest；不可删除零调用检查后把旧回放算成模型运行。

### 4.2 双方共用真实正文

定义单一的规范化可见证据对象；至少包含：

```text
instance_id, evidence_id, material, visible_sha256,
display_path, displayed_span, found, parseable, uncertainty
```

内部 provenance 另外保存真实 revision、原文件 hash 与原始行号；这些不是默认发给模型的 metadata。两组使用同一份已裁剪 raw evidence block。History 事件必须有 material，不能只保存 ID。SBS 不得到额外 gold hypothesis 或正确解释。

**检查最终 prompt，而不只检查 Python 对象。** 在每个步数发送模型前，比较两组原始入口和累计 evidence block 的字节/哈希、实际可见顺序、裁剪边界。两组生成的笔记允许不同，公共事实不允许不同。

采用同一总上下文预算。给 note 预留相同额度，再统一裁剪公共证据；不得因为 SBS 的 note 更长就只裁它的证据。不能保留必要材料时标 `context_insufficient`，不要偷偷把一组改为完整正文。

### 4.3 统一引用更新与读取绑定

- 每次更新先完整验证，再提交；失败不能留下一半修改的状态。
- support/counter 引用必须是当前 instance、当前 generation、已读取且确有材料的 evidence；allowed 未读不算观察。
- 不存在的 hypothesis、跨实例/跨 generation、非法范围、混入 fixture script 都要拒绝。
- 真实文件行号必须对原快照核实，不能把摘录第 1 行当成原文件第 1 行。
- `not_found` / 无材料 / 解析失败不是反证。运行失败与安全判断分开。
- 本轮一个主假设；不静默取 hypotheses[0] 忽略其他假设。
- 真实 runner 只接收 actor manifest，不加载 evaluator、advisory、补丁、ReplayScript 或配对映射。
- 输出结构错误可以返回 parse_error/unresolved，但不能按脚本补一个“正确”答案。

模型可见的是这个版本当时可获得的代码与中性功能说明。命名不得是 buggy/fixed、pair-role、CVE 等标签；不要伪造源码或承诺消除所有预训练污染。

### 5.4 逻辑要求与真人核验

对每对草案填写：实体、应成立的关系、要求来源、版本适用范围、两侧静态证据、反对当前解释的材料、缺失信息。原始审阅包留本地，Git 提交安全概要与核验状态。

要求的依据优先是对应版本的需求/接口契约/维护者规格。历史公告可供 evaluator 参考，不能给 actor 看答案；同类接口和模型推断只是线索。不能仅靠补丁修改推定整个业务规则。

允许真人未核验时先生成 **unscored** 模型响应并统计结构/引用错误。`accuracy/F1/GPC/reward=null`；不能用草案标签当 RL 奖励。真人确认记录必须由用户实际完成，模型不签名、不冒充两名标注人。

**核验解释对象要明确：** 模型 refuted 的只是它自己提出的某个假设，不能自动等同于目标漏洞不存在。未来语义评分还需要 hypothesis_matches_target 与 evidence_sufficiency；假设偏离目标不能奖励为“正确否定”。

### 5.5 有用的远程材料摘要

## 7. B05 — 冻结协议，运行第一批先导

### 7.1 G0 前置门槛

G01–G12 中涉及真实输入与实验记录的回归通过；actor 材料和模型身份通过校验；完整 pair 至少 1；本轮参数锁定。缺 catalog 不应阻塞自建测试；缺真人核验不阻塞 unscored 运行；缺真实版本材料则阻塞 paired 运行。

### 7.2 每个 episode 固定 4 个请求

输入是中性入口说明和初始代码，不给正确 B。两个条件都能保留自己产生的笔记，History 不是“没有记忆的弱基线”。

1. 只根据同样的初始事实形成当前假设/问题。History 输出普通笔记，SBS 输出结构化关系+支持/反证/未知项。
2. 固定读取第一份证据，保留同样累计原始正文，更新笔记。
3. 固定读取第二份证据，继续更新。只有一份证据则显式 no_more_material，不能把空白作反证。
4. 输出相同最终结构：`hypothesis`、`verdict`、`support_refs`、`counter_refs`、`unknowns`、`limitations`；verdict 为 supported/refuted/unresolved。

模型生成的结论是待评结果。结构验证通过不等于安全判断正确。unsupported label/confidence 不能变成 oracle reward。

每步的两个条件公共 evidence block 必须相同；各自 note 的区别才是表示干预。笔记统一 max_new_tokens=512；最终报告也为512。留存实际 token 数，不能声称 token 成本天然相等。

### 7.3 两个顺序与数量

先在 **1 对 / 2实例 / 2表示 / 1顺序** 上运行，共 4 episodes ×4 = **16 个主请求**。这是第一检查批，保留失败后再决定剩余批是否运行。

首批若 G0、模型身份、调用记录或单侧截断出现问题，停止真实比较并修工程，不能继续烧剩余预算。输出不好或 unresolved 本身不是删样本理由。

随后最多扩到4对，使用事先冻结 order_seed=17、29；计算两个具体顺序并记录。若两种顺序相同，只执行一次或标 duplicate_order，不称两次独立实验。首批是完整矩阵的子集，后续**不要重复计算**。

完整上限：4对 ×2版本 ×2表示 ×2顺序 ×4请求 = 128 主请求。

E0最多8 + E1最多128 + 格式修复/失败预留最多16 = 152，且总硬上限仍为192。多余预算不授权新模型或更多样本。每个响应最多一次仅修格式的模型重试；重试也计数，不能展示 gold 或指示改结论。

**本轮删除旧 R02 的可选 E2 分支实验。** Q/V 与分支回报留到下一轮，避免材料和模型尚未跑通就扩任务。

### 7.4 首次锁定后禁止的变化

不得看了结果后换病例、重新写入口、只调整一种表示、隐藏截断失败或 cherry-pick 最好输出。发现资料错误则生成新 generation 与新的协议版本，保留旧运行，并在分析中区分。

已完成的模型响应只能在模型/配置/输入/条件/步骤/版本等 key 全部匹配时复用；缓存命中不算新调用。不要因 Git 文档提交更新而误判代码相同或不同：run 记录真实 implementation SHA + runnable tree/config hashes。

### 7.5 本轮分析必须回答的五个问题

1. 实际完成多少个独立版本、完整对、episode、模型请求？分母是什么？
2. G0 是否都通过？真实 prompt 的公共证据对齐记录在哪里？
3. 模型主要失败是输出格式、证据引用、假设质量、规格不足还是上下文不足？
4. 在未做语义核验前，哪些是可以报告的工程指标，哪些必须 null？
5. 下一轮首要工作是增加标签核验、扩大模型、做价值数据，还是继续修输入？写事实与原因，不代替负责人下新轮计划。

至少选两条真实轨迹供分析；优先包含失败/unresolved。可发布的摘要写成“观察到了什么”，不要以小样本或本地模型排名宣布创新成立。

### 8.3 报告验证的实际语义

status 字段至少分开：engineering/data/model_run/human_annotation/delivery/review。参考模板，所有未观测数字为null而非0。旧 real_ready_count 留 legacy 字段。`review_status=pending` 仅指这次新提交待负责人审查。

### 8.4 A/B/C 提交与推送

1. **A实现**：固定代码、测试、任务、选择与配置。记录 `IMPLEMENTATION_SHA=$(git rev-parse HEAD)`。若之后修代码，重记真正运行所用的新SHA；不能把报告提交当实现提交。
2. 在A上实际执行测试和允许的模型运行。结果置独立目录，不覆写旧运行。
3. **B报告**：完成摘要、检查与run_index，明确对应A；提交后实际推送当前任务分支。
4. `git ls-remote origin refs/heads/research/naacl2027-r02` 获取远程SHA，核对与本地B一致；失败有限重试，禁force push。
5. **C回执**：`push_receipt.json` 存已观察到的B、推送退出码、核对时间；再提交并推送C，再核对最终远程SHA。
6. C文件不写自己的SHA，避免自引用循环。最终对话交接填写C的实际SHA。

若已存在未提交WIP，不把无关修改一起提交。不可逆操作、wrong origin、秘密暴露风险必须停止对应操作。正常推送失败不抹掉本地成果，记录 delivery=failed。
