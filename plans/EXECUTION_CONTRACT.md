# NAACL 项目执行规范 v1.0

> 研究负责人制定取舍；本地编程 agent 实现、运行、记录。不要把本文当作已完成的工作记录。

## 职责

研究负责人负责研究问题、方法选择、比较协议、指标口径、数据划分规则和下一轮决策。本地执行端负责按任务实现、读取允许材料、运行检查、保留原始结果、报告阻塞和推送。需要业务规范判断、标签真实性或作者资格的事项，必须保留给真人确认。

执行端可以选择等价的局部编码实现，不能自行更换研究问题、基础模型、数据类别、正负例口径、对比基线、奖励或测试集；不能因为结果不好而删样本、修改 gold 或只报告成功运行。用户称本地执行模型为 Grok-4.6，这只标识执行端，不自动成为实验模型身份，也不证明任何性能。

## 每个任务必须包含的八个字段

`ID / 目的 / 输入 / 操作顺序 / 预期输出 / 验收 / 禁止事项 / 失败处理`。

操作写成有限动作，不使用“自行探索最优方案”“补齐逻辑漏洞即可”等需要重新决策的指令。CLI 不存在时先实现或查明等价入口；不能抄写一个计划中的命令就声称它已运行。前置条件未满足不得跳过；失败最多两次局部修复，仍失败则保留日志并记录具体阻塞，继续不依赖它的任务。

## 真实性

区分 `not_started / running / passed / failed / blocked / not_evaluated`；not_evaluated 不是 0。数字只从实际文件和日志派生；手工摘要必须指向依据。示例、模板、fixture、真实材料、模型输出、真人核验和正式计分分别记录。不得把自评写成负责人验收，或用多次 AI 回答冒充独立真人标注。

## Git 与本地资产

不要把 data、local_data、artifacts、模型权重和原始日志整体推上 GitHub。维护 `reports/LOCAL_ASSETS.md` 和 `reports/local_assets/index.jsonl`，说明本地内容和远程可见证据。敏感文件不读取、不复制、不输出内容；不靠删除 gitignore 绕过发布检查。

每轮结束保存当轮快照 `reports/rounds/<ROUND>/LOCAL_ASSET_HANDOFF.md`，更新稳定入口。旧轮次记录不覆写。实现提交、结果提交、推送回执应可区分；推送后核对精确远程 ref。未推送成功不得写 delivery=completed。不得强推、删除 WIP 或自动合并默认分支。

## 负责人远程审查能证明什么

资产摘要和哈希可以证明记录之间的一致性、是否存在可追溯原始材料，不能自动证明材料语义真实、许可满足或结果正确。不能访问原始内容时标记 `content_not_remotely_reviewed`。为关键主张提供合规的最小摘录、可重建脚本或明确的真人核验；无法提供时保留限制，不提高验收等级。
